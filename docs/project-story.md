# 一个麻将游戏的六年

*从一次上班摸鱼的念头，到一个持续维护六年的个人项目。*

## 2020：一个不太正经的开始

2020 年，我开始了这个项目。

最初的想法很简单：做一个可以在命令行里玩的麻将小游戏。

当时我还在深信服工作，有一段时间项目需求迟迟没有确定下来，暂时也不需要做什么开发工作。但工作时间总不能一直无所事事。

当时公司对网络使用有监控，如果联网玩游戏，很容易引起注意。

于是我产生了一个想法：能不能自己做一个完全离线的小游戏，直接在命令行里运行，界面尽可能简单，不引人注目？

为了让它看起来不像一个游戏，我特意选择了纯英文的界面表示方式。即使程序运行起来，也尽量让它看起来像一个普通的命令行工具。现在回头看，这个决定还意外地催生了项目后来的语言系统。最初只是为了隐藏游戏属性而使用英文，后来逐渐发展成了可以切换语言的机制，再后来又增加了双语支持。

最初参考的是以前小霸王上的麻将游戏。游戏机制也比较特别：机器人在开局时就已经生成了一手不错的牌，玩家需要在有限的手数内努力胡牌。如果达到指定手数仍然没有胡牌，机器人就会获胜。

它并不是一个真正意义上的麻将 AI。机器人不需要理解复杂的麻将策略，只需要按照预先设计好的规则运行。

但即便如此，实现起来也没有想象中简单。

当时我对 Python 只有一点基础，很多东西都是边查资料边学习。那个年代写代码基本都是一个字母一个字母地敲，没有现在 AI 辅助编程这样的工具。

其中最让我花费精力的，是麻将胡牌判定。

当时在网上搜索了很久，没有找到合适的现成算法，只找到了一些关于胡牌判定的思路介绍。于是，我根据这些思路，自己写出了第一版 Python 实现。

光是 `JudgeIsWin` 这个函数，就花了一个多星期。

当时还遇到了 Python 深拷贝和浅拷贝的问题。对于一个需要不断尝试不同牌型组合、又要恢复原始手牌状态的算法来说，这些问题并不容易解决。

后来，围绕这段代码不断增加功能：普通胡牌、七小对、十三幺、听牌、碰牌、杠牌……

最初它真的只有一个判断能不能胡牌的功能。后来的听牌判断、积分计算等，都是在原有代码上逐渐补充进去的。

现在回头看，里面有不少不规范的命名，也留下了很多历史包袱。但有些核心逻辑，至今仍然让我感到自豪。

尤其是最初自己摸索出来的胡牌判定算法。它不一定没有问题，但经过了这么多年的使用，仍然是整个项目中非常重要的一部分。

## 2020—2021：不断完善

随着功能越来越多，项目也经历了很多次迭代。

从最初简单的胜负判断，到后来增加胜率统计、牌局日志、配置文件、难度调节、积分系统、多语言支持、测试模式……

我逐渐开始关注程序本身的稳定性。

现在再看当年的 CHANGELOG，经常能看到一些简单得不能再简单的记录：

- 修复若干问题。
- 优化代码逻辑。
- 调整游戏难度。
- 修复一些牌型判断错误。

遗憾的是，当年没有养成详细记录问题的习惯。现在已经完全想不起那些「若干问题」究竟是什么了。

不过，至少这些记录还保留着项目不断成长的痕迹。

## 2021：一次 Go 语言重构

后来，我开始学习 Go。

当时对 Go 也只有一点基础，基本停留在知道语法的程度。

我觉得，与其重新找一个练习项目，不如把这个已经相对成熟的麻将游戏重新实现一遍。

于是，v8.0.0 发布。

这次重构让我学到了不少东西。

例如 Go 的参数传递方式，就和我之前对 Python 的理解有很大不同。通过重构这个项目，我开始真正理解 Go 中值传递、指针以及数据结构之间的关系。

当然，重构并没有想象中顺利。

原本 Python 版本已经相对稳定，但迁移到 Go 之后，又暴露出不少问题。随后又经历了很多版本的修复和调整。

虽然付出了不少时间，但这次经历让我对 Go 语言有了更深入的理解。

项目也从一个最初用于摸鱼的 Python 小程序，逐渐变成了一个长期维护的 Go 项目。

## 一段差点丢失的代码

这里还有一段比较特别的经历。

当时准备离开深信服，想着把这个自己写了很久的项目带出来。

但项目是在公司内网开发的，所有代码和提交记录都保存在内网 GitLab 上。没有办法直接把仓库带走。

最后只能对着内网 GitLab，把所有源码文件一个字母、一个字母地抄出来。

这件事远比想象中麻烦。

代码层级多了，很容易抄错。比如一个 `return` 究竟应该放在某个 `{}` 里面还是外面，看起来只是一个很小的区别，却可能造成完全不同的执行结果，而且这种错误还很隐蔽。

当时也没有更好的办法，只能尽可能仔细地核对。

由于时间有限，最终只来得及把 Go 版本的源码全部抄出来，原来的 Python 版本和早期提交记录还是没能保存下来。

后来，这份代码又经过了几次修复和迭代。

再后来换电脑，代码也找不到了。

一度以为这个项目就这样彻底消失了。

直到后来，终于在 iCloud 云盘里找到了一个非常久远的备份。

有意思的是，找到的正是当年刚刚抄出来的那份代码，甚至还保留着几个我记得后来已经修复过的 Bug。

就这样，绕了一大圈，最后找回来的竟然是当年那个不太完整的版本。

这就是现在这个项目的雏形。

说起来有些幸运。

如果当时没有找到这份备份，这个持续了几年的小项目可能真的就只剩下一些零散的回忆了。

Python 版本最终还是没有找回来。早期的提交记录也已经丢失，现在能够看到的只有当年留下的 CHANGELOG。

有时候看到那些简单的修复记录，会忍不住后悔当年为什么没有多写几句话。

但至少，项目还在。

## 2026：AI 时代的重新出发

后来，AI 时代来了。

我发现 AI 可以帮助我完成很多以前想做、却因为技术能力、时间或者精力限制而没有实现的事情。

于是，我重新开始认真维护这个项目。

这一次，我不只是想增加几个游戏功能，而是希望把它做得更好。

v9.1.0 是一个新的开始。

我为它增加了结构化 JSON 牌局录制、确定性回放、状态哈希、严格校验、快照观看和单步调试等功能。

以前遇到一个 Bug，可能需要花很多时间手动复现。现在可以保存一场完整牌局，重新播放，并在出现差异时定位具体帧、回合和字段。

这些功能对于一个命令行麻将小游戏来说，似乎有些过度设计。

但我很享受这个过程。

我还想继续做很多事情：

- 改善命令行界面，让牌张和牌局信息展示得更漂亮。
- 尝试增加 GUI，让游戏不再局限于命令行。
- 重构那些经过多年迭代、已经不够优雅的代码。
- 重新规划积分系统，让游戏奖励更加合理。
- 实现一个真正的麻将机器人。

最后一件事，是我一直想完成的目标。

我希望机器人能够像一个真正的麻将玩家一样，理解自己的手牌，判断听牌，选择出牌，能够吃、碰、杠，并且有自己的策略。

而不只是像最初那样，开局就拿好牌，等着玩家输掉游戏。

## 写在最后

从 2020 年到 2026 年，六年时间过去了。

最初只是因为工作暂时没有事情做，想写一个摸鱼小游戏。

没想到它一直延续到了今天。

这六年里，我学习了 Python 和 Go，换了工作，接触了越来越复杂的技术，也逐渐从一个刚刚开始学习编程的人，成长为一名有多年经验的后端工程师。

但这个小项目一直留在这里。

现在重新打开它，看到那些奇怪的变量名、自己写的算法、反复修改的积分公式，还是会想起当时的日子。

有些代码现在看来并不漂亮，有些设计也早已不符合今天的工程习惯。但我不打算否定它们。

因为它们记录着当时的思考，也记录着那个阶段的自己。

后来，在 AI 的帮助下，我终于把它整理并上传到了 GitHub。

某种意义上，它终于有了一个可以长期保存的地方。

我希望它能继续更新下去。

至于未来还会有多少个版本，我不知道。

但我希望它能继续陪伴我。

我最初只是想自己玩得开心。如果有一天，除了我以外，也有人愿意下载它、玩它，那就更好了。

**这是一个从 2020 年开始，至今仍然没有结束的小项目。**

2026 年。
