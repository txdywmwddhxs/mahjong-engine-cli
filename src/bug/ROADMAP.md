# 项目后续提升方向（Roadmap）

本文记录本项目在 **保留挑战式玩法、不重构机器人逻辑** 的前提下的工程化进展。v9.1.0 聚焦可复现、回放、判和可靠性和职责拆分；公平对战 AI 与整体对战引擎重构留到后续版本。

## 已有基础

- 已迁移到 **Go Modules**（`go.mod`），内部包 import 已改为模块路径。
- 已修复跨平台路径拼接问题，正常游戏启动时创建配置、日志和 pid 目录；回放观看和校验不创建运行目录。

## v9.1.0 本期完成

- **统一每局随机性与 seed**
  - 洗牌、机器人牌型生成和难度 limit 使用同一个每局 RNG；连续牌局的随机状态独立。
  - 日志和回放记录实际使用的 seed。精确复现通过保存初始状态和语义决策的回放完成；仅有 seed 不能替代完整回放。
- **回放与黄金用例（Golden tests）**
  - 支持 JSON 录制、严格校验、快照观看及单步前进、后退和跳转。
  - 日志默认嵌入压缩回放块，可复制分享；支持从整份日志、回放块或标准输入读取，按牌局 ID 选择。
  - 覆盖七小对、十三幺、一条龙、碰、明杠、暗杠、加杠、听牌和结算回归；固定种子和语义输入锁定关键事件与结果。
  - 保存重构前的典型牌局回放基准，对比中间状态、计分项顺序和结算明细。
- **结构化事件记录与诊断**
  - 保存完整初始状态、决策编号与动作、接受结果、事件快照、状态哈希及结算。
  - 补充 seed、版本、回合、手牌、决策和计分信息；校验在首次分歧时报告帧号、回合和字段差异。
  - 最新一局中断、复制截断或回放损坏时明确报错，不静默回退到上一局。
- **判和与听牌可靠性**
  - 校验牌名、手牌与副露合计的同牌数量、副露组合、总牌数及杠数量；听牌检测排除需要第五张同牌的候选。
  - 使用独立完整回溯判定器对照 2,190,387 个合法样本，包含单花色穷举、随机牌、构造和牌及变体、七对和十三幺，未发现误判或漏判。
  - 大规模实验是正确性验证，不替代性能 Benchmark，也不是所有混合花色牌型的完整穷举。
- **判和与计分职责拆分**
  - `JudgeIsWin() bool` 只判断和牌，不修改牌序、积分或日志；移除 `final` 参数。
  - `hand` 包负责输入校验与牌型分析，`score` 包负责牌型奖励、缺门奖励和分数计算，`player/scoring.go` 集中游戏内计分记录。
  - `GetScore` 不再修改输入计分项；保持现有计分规则和回放格式。
- **README 模式说明**
  - 已明确当前为挑战式玩法，包括回合限制和失败后展示机器人牌张；公平对战 AI 为后续目标。

## v9.1.0 阶段性完成

- **解耦 I/O 与规则推进**
  - 已支持注入语义输入、无交互调用、等待函数替换及事件录制；回放校验不依赖终端文案、语言或等待时间。
  - 核心牌局流程仍调用展示与翻译接口。后续继续向“引擎产生事件、CLI 渲染交互”的边界收敛，尚未完成整体解耦。
- **错误处理收敛**
  - 已处理 EOF、输入中断、回放损坏和校验分歧；中断牌局不计入战绩，运行异常提供定位信息。
  - 配置、日志归档等部分文件操作仍有 panic 或忽略错误。后续统一返回 error 或提供明确降级处理，不将此项标记为整体完成。

## 后续：可维护性

- **显式状态机化**：明确发牌、摸牌、判和、询问、碰杠、出牌和结算阶段，整理 `isWaiting/isClear/condition` 等字段。
- **减少魔法数与集中配置（本期完成常量整理）**：牌种、同牌数量、手牌与面子大小集中到 `card/constants.go`；挑战模式概率、limit 范围、奖励回合及安全限制集中到纯 `rules` 包；计分公式参数集中到 `score/constants.go`。引擎与回放校验共用限制，显示延迟与日志传输阈值在所属模块具名管理。后续仍可将模式参数扩展为可选择的配置。
- **显式玩法模式**：将挑战式机制作为 mode/config，便于后续扩展公平对战。

## 后续：性能（先量化，再优化）

- 为 `JudgeIsWin` 和 `CheckIsWaiting` 建立 Benchmark，测量耗时及内存分配。
- 根据基准结果减少重复排序、切片复制与临时对象分配。
- 稳定后考虑将判和、听牌从字符串切片逐步迁移到计数数组或位图。

## 后续：工程化与发布

- **发布验收入口**：已增加 `./scripts/check.sh release`，统一执行静态检查、race 测试、CLI 集成与黄金回放、大规模判和对照、256 局种子复现、当前平台发行包验证及覆盖率门槛。通过代表满足现有验收范围，不代表所有情况无缺陷。
- **CI**：接入 GitHub Actions，运行 `go test ./...`；现有本地检查脚本不等同于 CI。
- **Release 策略**：已有打包脚本和当前平台发行包验收；仍需确定 macOS/Linux/Windows 的正式发行目标、完成各目标平台的运行验证，并明确配置/日志目录策略。
- 已统一以根目录 `VERSION` 作为文件版本来源；发行包编译时注入该版本并附带匹配的 `VERSION`，测试包使用 `dev`。changelog 仅记录更新历史，不再参与版本解析。

## 公平对战 AI 前置

- 已具备 seed、完整回放与可注入输入的无交互执行能力。
- 后续继续完成引擎与展示解耦，并通过 Benchmark 评估批量仿真能力。
- 基础稳定后，再推进机器人手牌维护、策略系统和公平对战规则（取消硬判负、对称摸打等）。
